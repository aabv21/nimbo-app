| | |
|---|---|
| Scope | The Postgres schema the migrations build (`public`, `private`, the `pg_cron` jobs, the Vault and `pg_net` as Nimbo uses them): RLS and policies, table, column, sequence and function privileges, `search_path` and volatility, keys, constraints and indexes, the retention periods against the privacy policy, the zone check, the consent tables and `supabase db lint`, at `b6b7365` on `feat/hardening`. Supabase's own schemas (`auth`, `storage`, `realtime`) are out of scope. |
| Skill | `postgres-tools:sql-authoring`, its optimization checklist used as the audit checklist: indexes confirmed with `EXPLAIN (ANALYZE)` over synthetic rows, set-based statements, explicit NULL handling, bounded result sets. |
| Date | 2026-11-28 |
| Fixes | `supabase/migrations/20261130120300_database_audit.sql`, the CI step `pnpm db:lint`, the privacy policies' push ownership period, and one comment in `supabase/functions/monitor/handler.ts`, in the Task 7 commit (`wip(task 7): database audit`, squashed later into the milestone commit). |
| Companion audits | [`security.md`](security.md), [`api.md`](api.md) (its `api_audit.test.sql` pins the exact client grant sets and function lists; this audit does not repeat them). |

Statuses as in [`security.md`](security.md): `fixed` names its test; `accepted` gives the reason and the cost; `deferred`
waits for a live project or a later task. A control that held under test but had no regression pin is `fixed` with the
new pin; one already pinned is `accepted`.

## Method

- **Catalog queries** (`supabase/tests/database_audit.test.sql`): each rule is one query that lists the objects breaking
  it, asserted empty, so a later migration that breaks a rule fails `pnpm db:test`. Written first; five failed against
  `b6b7365` (rows DB-01 to DB-05 below), all pass after the migration.
- **Plans**: `EXPLAIN (ANALYZE)` of the prune's deletes and the receipts read over synthetic rows (200,000 signals for
  2,000 users, 100,000 push tickets, 615,000 usage counters), inside a rolled-back transaction.
- **`supabase db lint --local --level warning`** (plpgsql_check over `public`, `private` and `extensions`): one warning
  before, none after; now `pnpm db:lint` in CI.
- **The privacy policy's retention list** (`docs/privacy-policy.md#retention`) against `prune_expired_caches()` and its
  job.
- **TypeScript lists** the database mirrors: the condition pack, `DAILY_LIMITS` and the generated `Constants`.
