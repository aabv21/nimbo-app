**Statuses.** `fixed`: the code, config or a missing regression test changed here, and the row names the test.
`accepted`: the control holds or the risk is taken on purpose; the row gives the reason and the cost. `deferred`: it
needs a live account or native work outside this repo's rules, and is listed under "Deferred live checks" or in the
owner runbook.

**The `security-review` pass.** No finding reached the skill's bar (confidence 8/10 or more of a concrete, exploitable
vulnerability): every user-facing function derives the user from the gateway-verified JWT, every write is a
`security definer` RPC that filters by `auth.uid()`, no SQL is built from strings, outbound URLs come from the
environment, and no secret is in the tree. The rows below are the hardening and evidence the audit scope asks for.

| SEC-13 | medium | `supabase/functions/delete-account/handler.ts` | `delete-account` asks for no recent sign-in: a stolen, unexpired access token can delete the account for good.
