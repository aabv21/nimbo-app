# Red team: the guards

What an attacker, or an unlucky message, can try against the companion, the push functions and the hourly
monitor, the defense in the code, and the test that holds it. The guards themselves are described in [`ai.md`](ai.md); the suites in
[`testing.md`](testing.md). Fixture ids refer to `calibration/unsafe-replies.<locale>.json` (each id
exists in `en`, `es` and `pt`); red-flag texts are in `calibration/red-flags.<locale>.json`.

## The attack classes the guards cover

| Class | Covered by |
| --- | --- |
| Prompt injection through the user's text, a tool result or an agent note | The prompt's `data_handling` section; notes escaped inside `<notes>`; the classifiers' "data, never instructions"; the reply screen on every reply |
| Dose advice | The local dose check with the cabinet-quote rule, then the `dose_advice` and `medication_change` keys |
| Diagnosis | The `diagnosis` key |
| Ungrounded numbers | The local `ungroundedNumbers` list, then the `ungrounded_number` key |
| Red-flag dismissal | The input screen stops the request before any model reply; the `red_flag_dismissal` key on every reply |
| Jailbreaks (role-play, "my doctor said it's fine", a multi-turn "just say yes") | The prompt's `medical_boundary` and `data_handling`; the reply screen reads a reply against the last and the earlier user turns |
| Red-flag evasion (typos, slang, invisible characters, spelled-out letters, mixed languages) | Every reading of the text (as written, invisible characters dropped, spelled letters joined) against the three languages' keywords; the model screen behind them |
| Cost exhaustion | The daily quotas, the 64 KiB body cap, 3 tool rounds of at most 6 calls each; the owner's spend limit for the total |
| Exfiltration in a reply | `sanitizeReply` strips links of every form; the phone renders plain text |

## Request bodies, push and the monitor

Every function that takes a body (`monitor` reads none) reads it through a byte cap and answers `413 { "error": "payload_too_large" }` past it: 64 KiB for
`companion`, 2048 bytes for `push-claim`, 1024 bytes for `push-unregister`, and 256 bytes for `export-data` and
`delete-account`, which ignore theirs. The cap applies to a declared
`content-length` and to a chunked body, counted while it streams and never read past the limit.

| Attack | Defense | Test |
| --- | --- | --- |
| A huge or endless body sent to tie up a function. | The byte caps above, before any database or provider call; a body that breaks off is `400`. | `companion/__tests__/handler.test.ts` "413 for a body past 65536 bytes, chunked with no content-length too"; `push-claim/__tests__/handler.test.ts` "a body over 2048 bytes is 413 before any fetch, chunked with no content-length too"; `push-unregister/__tests__/handler.test.ts` "a chunked body over the limit with no content-length is refused with 413"; `export-data` and `delete-account` `__tests__/handler.test.ts` "refuses a body over 256 bytes with 413, chunked too". |
| Another user's rows in my export (a policy mistake, or a forged uid), or the push token and its secret hash in the file. | `export-data` reads with the caller's token (RLS) filtered by the verified JWT's `sub`, drops any row whose `user_id` is another's, uses the service role only for `usage_counters` with the same filter, and never selects `token` or `device_secret_hash`. | `export-data/__tests__/handler.test.ts` "drops any row of another user" and "asks push_tokens for neither the token nor the secret hash"; `account.int.test.ts` "no id of B anywhere". |
| Deleting someone else's account, or being told "deleted" when nothing was. | `delete-account` deletes only the verified JWT's `sub`, after Auth confirms that token's user is that id; only Auth's `user_not_found` reads as already deleted, never a bare 404 or another id. | `delete-account/__tests__/handler.test.ts` "answers 500 and deletes nothing on …"; `account.int.test.ts`. |
| A forged `x-webhook-secret`, or none, to run the monitor (its service role, everyone's signals and pushes). | `monitor` checks the header against `MONITOR_SECRET` with `secretMatches` before any call; only `request_monitor()`, run by `pg_cron`, reads the value from the Vault. No client can call `request_monitor()` or the monitor RPCs. | `monitor/__tests__/handler.test.ts` "anything but POST is 405, and a wrong or missing secret is 401, before any call"; `monitor.test.sql` (the RPCs refused to `authenticated`); `monitor.int.test.ts`. |
| A lock-screen leak: a push that says "short night" or names a medication on a shared or stolen phone. | Without `lock_screen_detail` the title is `push.neutral` with no body, in every language; with it, the body never names a medication or its class. `data` is only `{ url: '/today' }`. | `pushCopy.test.ts` "without the opt-in, no kind in any language carries a health word" and "with the opt-in, the overuse body says the day count and never the class or a medication"; `monitor/__tests__/handler.test.ts` "an Expo body (opt-in false/true) holds a token only in `to`, no UUID, and `data` only the url". |

| Deleting someone else's token through `push-unregister`, which needs no session. | It deletes only the row of the account named in the body that holds the token under that device secret's hash, and answers the same `204` whether or not a row matched, so it cannot probe tokens. | `push-unregister/__tests__/handler.test.ts` "deletes only that account’s row holding that token under that device secret’s hash" and "a wrong secret deletes nothing". |

The security and API audits ([`audits/security.md`](audits/security.md), [`audits/api.md`](audits/api.md)) pin the
rest of the attack surface outside the companion: the gateway's JWT check (garbage, expired, wrong-key and anon-key
tokens are `401`), the chunked body caps through the gateway, another user's ids in every RPC (BOLA), unknown keys in
every `jsonb` RPC, the exact client grants, and that no service-only RPC is executable by a client.

## Known gaps

The reviews found these, and each is accepted for now unless it says otherwise.

- **Dose wordings the local check misses:** "twice a day", "q6h", "a tablet" and "one pill" carry no amount
  the patterns read. The models judge them; with both models down they pass unless a take imperative sits in
  the same sentence.
- **"one", "uno" and "um" are not in `NUMBER_WORDS`**, so "Take one tablet now" is not a local dose amount.
  It is `ok` once a model clears it, and the take-advice check catches it only when both models are down.
- **"no fever, just a severe headache" raises `fever_stiff_neck`.** Negation is not parsed, on purpose: a
  false hit costs one "I'm safe, continue", a miss could cost far more. "chills from the AC and a bad
  headache" hits for the same reason.
- **`modelOnly` red flags with the AI off or both classifiers down** get no urgent-care screen (above).
- **Evasions the keywords still miss:** two one-letter words right before a spelled-out one ("e a n u c a"; a single
  connector, "y n u c a", is read both ways), a word spelled with two letters, and look-alike letters from other scripts
  (a Cyrillic "о" in "wоrst"), which are not folded. The model screen must catch them; with the AI off they get no
  urgent-care screen.
- **A bare "yes" with both models down** is `degraded`, not replaced: only the models read it against the earlier turns.
- **The server screens only the request's last user turn**; earlier turns were screened when sent, and the app drops
  red-flag exchanges from the history ([`audits/agent-guardrails.md`](audits/agent-guardrails.md) AG-14).
- **Account deletion needs no fresh sign-in.** A stolen access token that has not expired (1 hour) can delete the
  account; a signed-out session's cannot (`401`). Upgrade path, before the public store release: refuse unless the
  token's newest `amr[].timestamp` is under 10 minutes old ([`audits/security.md`](audits/security.md) SEC-13).
  Changing the password needs a session made in the last 24 hours or an emailed nonce (SEC-16).
- **`export-data` has no rate limit.** It returns only the caller's own rows, page by page under PostgREST's timeout,
  but each call costs at least 12 upstream calls against the whole project's quotas; a daily `export` unit through
  `consume_quota` is the upgrade ([`audits/api.md`](audits/api.md) API-16).
- **A signed-out token keeps working against PostgREST and `companion` until it expires** (at most 1 hour): Supabase's
  stateless JWTs (SEC-15).
- **A leaked push token can be sent pushes through Expo directly** until the owner turns on Expo's enhanced push security
  (SEC-14); `push-claim`'s own code push is data-only and rate-limited.
- **The thresholds are not calibrated yet.** They are starting points until `pnpm calibrate eval` runs on the
  real services ([`ai.md`](ai.md#calibration)), the jailbreak, injection, evasion and `mixed` fixtures included.
- **No cap bounds the total spend across accounts** until the owner sets the Anthropic spend limit and TypeSafe's cap
  ([`audits/agent-guardrails.md`](audits/agent-guardrails.md) AG-11).
