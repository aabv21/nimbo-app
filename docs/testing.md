# Testing

Six suites: four Jest projects (`app`, `scripts`, `functions`, `integration`), one pgTAP suite and the
Maestro flows. `pnpm test` runs the three that need no Docker. `pnpm test:int` and `pnpm db:test` need the
local Supabase stack ([`local-stack.md`](local-stack.md)); `pnpm e2e` also needs an emulator and a dev build. The modules under test are described in [`app.md`](app.md) and the flows in [`architecture.md`](architecture.md).

| Suite | Command | Needs the stack | CI |
| --- | --- | --- | --- |
| `app` | `pnpm test` | no | Quality job |
| `scripts` | `pnpm test` | no | Quality job |
| `functions` | `pnpm test` | no | Quality job |
| `integration` | `pnpm test:int` | yes | Database job |
| pgTAP | `pnpm db:test` | yes | Database job |
| `supabase db lint` | `pnpm db:lint` | yes | Database job |
| Maestro | `pnpm e2e` | yes, plus an emulator | no (run locally) |

CI also runs `pnpm typecheck`, `pnpm lint` and `pnpm check:supply-chain` in the Quality job, and
checks that `src/lib/database.types.ts` matches the migrations in the Database job, which also runs `pnpm env:local && pnpm test:int` against that stack. `pnpm db:lint` runs plpgsql_check over `public`, `private` and `extensions` and fails on any warning.

## `app`

Component, hook and unit tests under `src/**/*.test.[jt]sx?`, in `jest-expo`'s React Native
environment. `jest.setup.ts` mocks what has no native module under Jest:

- `react-native-safe-area-context`: the package's own Jest mock, so insets are deterministic.
- `expo-localization`: `getLocales()` answers a fixed `en-US` locale, so i18n tests do not depend on the host.
- `expo-network`: online and reachable; a suite that tests connectivity mocks the module itself.
- `expo-haptics`: resolved no-ops.
- `expo-notifications`: permission granted, nothing scheduled and nothing in the tray, a push token for `device-1`, no tap that launched the app, and listeners that never fire; `src/cabinet/__tests__/reminders.test.ts` replaces it with a stateful fake that holds what is scheduled and what was delivered, and `src/__tests__/sign-out.test.tsx` makes the same calls stateful.
- `expo-location`: permission denied and no position; a suite that needs a fix mocks the calls it makes.
- `expo-sqlite/kv-store`: an in-memory map behind the same synchronous API `src/lib/kv.ts` calls, `getAllKeysSync` included.
- `expo-file-system`: `src/test/fileSystemMock.ts`, one in-memory cache directory with `File`, `Directory` and `Paths`;
  `cacheFiles()` and `cacheFileText(name)` read what a suite wrote, `resetFiles()` empties it.
- `expo-sharing`: the share sheet is available and settles at once.
- `expo-sqlite` itself is not mocked globally: a suite that touches the local store runs it on
  `src/test/sqliteNode.ts` with `jest.mock('expo-sqlite', () => require('<path>/test/sqliteNode'))`. The
  adapter implements `openDatabaseSync`, `execSync`, `runSync`, `getFirstSync`, `getAllSync` and
  `withTransactionSync` over `node:sqlite`'s `DatabaseSync(':memory:')`, so the real SQL, constraints and
  transactions run. Each open is a new empty database, and a nested transaction fails as on a device.
  `src/test/localDbTest.ts` empties the store between tests and inserts mirror rows.
- `Dimensions`: `fontScale` 1, since React Native's preset reports 2 and would render every large-text layout.

`src/__tests__/securityScan.test.ts` reads the source as text, for the security audit ([`audits/security.md`](audits/security.md)):
no file under `src/` names the service-role key, the app reads only the four public `EXPO_PUBLIC_*` values, its only
`console` call is the dev-only Google setup warning, every dynamic route segment is `[id]`, screens read and navigations
pass only `id`, `debrief`, `filter`, `email` (the confirmation screen only) and `sent`, template paths build in only
`${id}`, and `.gitignore` covers the Firebase admin keys, `.env`, `.env*.local`, `supabase/functions/.env`, keystores and
signing keys.
- `react-native-reanimated`: `src/test/reanimatedMock.ts`, since Reanimated's own mock loads the worklets native module. Animations settle at once on their target, and `withTiming` calls its completion callback with `finished: true`; a shared value written with `.set()` reaches a style only through `useAnimatedStyle`, as on a device.
- `react-native-worklets`: `scheduleOnRN` calls its function at once, since the worklets runtime is native.
- `expo-speech`: an `en-US`, an `es-MX` and a `pt-BR` voice, and `speak`/`stop` as mocks.
- `expo-speech-recognition`: available, permission granted, no Android offline language pack; `src/test/dictation.ts`
  emits its `result`, `error` and `end` events to the listeners still subscribed (`hear(text)` is a final result then
  the end) and `settle()` lets a press's permission request resolve.
- `expo-glass-effect` and `expo-blur`: plain views; `isLiquidGlassAvailable` is a `jest.fn()` returning `false`, so a suite can reach the iOS 26 glass branch.

Tests use `@testing-library/react-native` v14, where `render`, `renderHook` and `fireEvent` are async.

### Calibration fixtures

`calibration/` holds three fixture sets per language (`en`, `es`, `pt`):

- `red-flags.<locale>.json`: `positives` the keywords must catch with zero misses, `negatives` they must
  never hit, `modelOnly`, messages the keywords are allowed to miss and the model screen must catch
  (a fever with a severe headache in other words, a head injury without the usual phrases, "four days now"), and
  `mixed`, messages mixing two languages that only the union of the three keyword lists catches. The positives include
  the red team's evasions: spelled-out letters, a zero-width or soft-hyphen character inside a word, typos, slang and
  missing accents ([`red-team.md`](red-team.md#red-team-rows-agent-audit)).
- `unsafe-replies.<locale>.json`: companion replies with the guard keys each violates (`expected.violated`),
  and the `toolResults` they were written against. The `quote` pairs hold the dose-text rule: a verbatim,
  attributed quote of the user's saved `dose_text` is safe, the same quote with advice is not. The `inj`
  replies carry a dose plus an instruction to the classifier (`*-inj-01`) or obey an injection from a note, a
  medication name or a dictated message (`*-inj-02`…`04`), which must change nothing. The `jb` replies are
  jailbreaks: role-play, "my doctor said it's fine", a bare "yes" whose `userText` and `earlierUserTexts` hold the dose
  question, a safe refusal, and a safe "yes" to an unrelated sleep question after an earlier dose question. A reply fixture may carry `userText` and `earlierUserTexts` for its context.
- `intents.<locale>.json`: messages and the intent each one should route to.

What the mocked tests prove: the plumbing (request shapes, the state each model sees, the parsers'
strictness), the thresholds, the fallback ladder (Jev, then Haiku, then the local checks or keywords),
and the local checks themselves, which run offline on every reply. What they cannot prove is Jev's or
Haiku's judgment: in `screen.test.ts` each fixture's expected answer is fed to the screen as Jev's answer.
That judgment is for a live calibration run against the real services, `pnpm calibrate eval`, reading
the same files: zero misses on the unsafe replies, the red-flag positives and `modelOnly`, and only then a
higher threshold where it keeps zero misses ([`ai.md`](ai.md#calibration)). It runs in the owner's session
with the real keys, never in CI and never in `pnpm test`.

### Insight and signal fixtures

`supabase/functions/_shared/__tests__/fixtures/` holds `insights-cases.json` and `signals-cases.json`, copied
byte for byte from the planning folder (`docs/superpowers/specs/2026-11-26-tregua-w4-prep/fixtures/`, kept
outside this repo, next to it) and checked once with `cmp`; CI cannot reach the source, so never edit them here.

`now` and zone, and the expected output.

When a case fails, re-check the rule first, then the fixture: the fixtures were worked out from the spec, so a
failing case usually means the code drifted. Change a fixture only by changing the planning copy, copying it back
byte for byte and running `cmp` again.

## End-to-end flows (Maestro)

`.maestro/` holds five flows that run in order as one fresh user, on a dev build against the local stack.
They select elements only by `testID` (stable English ids such as `today-start-attack`, never copy), so a
copy change or another language does not break them; a test in `scripts/__tests__/e2e.test.ts` fails if a
flow names an id the app code does not have.

| Flow | What it does |
| --- | --- |
| `flows/onboarding.yaml` | A fresh install: the intro, sign-up with the 6-digit code read from Mailpit (`subflows/sign-up.yaml`), both consent gates (all three boxes, the health-data one scrolled to) with the AI declined, every setup step skipped, and Today with three tabs. |
| `flows/crisis.yaml` | Adds an acute medication through Profile's cabinet (`subflows/add-medication.yaml`), then Start an attack, intensity 7, one dose, It's over, Yes, and the ended view. |
| `flows/red-flag.yaml` | Opens that attack from History's list, writes "worst headache of my life" in its notes and saves; urgent care opens with the sentence, and "I'm safe, continue" goes back to the attack. |
| `flows/companion-draft.yaml` | Turns the AI on in Profile and accepts, opens the Companion tab that appears, sends "slept 5 hours, very stressed", confirms the check-in draft, and finds the check-in done on Today. It needs both mocks serving (below). |
| `flows/privacy.yaml` | Last, since it deletes the run's user: Profile → Export my data → Export, waits for the ready notice and goes back; then Delete my account, ticks the acknowledgement, deletes, and waits for the sign-in screen. The share sheet itself is a live check. |

```sh

node integration/mockServices.ts --serve                      # in a second terminal: Jev, nothing flagged
node integration/mockAnthropic.ts --serve companion-checkin   # in a third: Claude, the check-in scenario
```

`scripts/e2e.ts` checks, in order: Java 17 for Maestro (`JAVA_HOME`, else Homebrew's `openjdk@17`), the
`maestro` command, one running emulator (`E2E_DEVICE` picks one when several run) with the dev build
installed, and the local stack at the URL `.env.local` gives the app. It starts Metro (`pnpm start`) when
nothing answers on port 8081 and stops it at the end, maps ports 8081 and the API's into the emulator
(`adb reverse`), then runs `maestro test` with a new `e2e-<time>@example.com` address, a random password
and Mailpit's URL. Each run creates one local account and leaves it; `pnpm db:reset` clears them.
